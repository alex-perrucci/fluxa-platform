# Fluxa POS

Flutter client generated by **Frontend Block 01 — Foundation, authentication and operational context**.

## Run

Development:

```powershell
flutter run -t lib/main_development.dart --dart-define=API_BASE_URL=http://localhost:3000/api/v1
```

Test environment:

```powershell
flutter run -t lib/main_test.dart --dart-define=API_BASE_URL=https://test-api.example.com/api/v1
```

Production:

```powershell
flutter run -t lib/main_production.dart --dart-define=API_BASE_URL=https://api.example.com/api/v1
```

`API_BASE_URL` is mandatory outside development. The URL must include the backend prefix `/api/v1`.

## Architecture

The app uses a feature-first structure with explicit models and thin data/domain/presentation layers. Riverpod provides dependency injection and state exposure; Dio owns HTTP concerns; GoRouter protects routes; secure storage contains tokens and the stable installation identifier.
